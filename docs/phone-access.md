# Phone access from the desktop app (macOS, Tailscale Funnel)

This document says what the setup wizard of the desktop app builds for phone use, what that makes reachable from the internet, how to switch it off again, and what it does **not** solve. It is about one computer that is both the place where the mail account lives and the server for the phone. It is not about the author's own server setup (see [operations.md](operations.md)).

**State.** Built and used for real on one Mac with one iPhone on 23 and 24 November 2026. Not built for Windows or Linux. Tailscale Funnel is the only tunnel the wizard sets up. The wizard also lists ngrok and Cloudflare Tunnel, marked "coming soon"; they do not exist yet.

## What the wizard sets up

| Part | What it is |
| --- | --- |
| Background service | A LaunchAgent of the user (`de.politzer.mailassistant.remote`, no administrator rights). It runs the HTTP server of the bundled program with the data folder as its only setting. It starts at login, restarts only after a crash, and logs to `~/Library/Logs/Mail Assistant`. |
| Settings file | `remote.json` in the data folder. It holds the public address, the hash (scrypt) of the sign-in passphrase (never the passphrase itself) and the switch for neutral tool names ([why](#voice-mode-on-the-iphone)). The server reads it at start. A setting in the environment still wins. |
| Tunnel | A Tailscale Funnel for port 8430 only (`tailscale funnel --bg 8430`). Tailscale itself keeps the rule, also across restarts of the Mac. A rule that somebody else has set up on the same HTTPS port is never overwritten. The administration of the app has no route through it ([decision 0003](decisions/0003-admin-access-never-through-the-public-tunnel.md)). |
| Sign-in passphrase | Generated by the app, shown once, stored by the person in a password manager. The connector sign-in asks for it. Creating a new one makes the old one invalid. |
| Connector | The person adds a custom connector in claude.ai with the address `https://mac.example.ts.net/mcp`. The app cannot do this for you. |
| Passkey on the phone | A separate step. A passkey belongs to the address, so the phone gets its own. At most two passkeys exist in total, and the computer's own passkey counts. |

The wizard shows the public address before anything changes, asks for a tick, and then checks the result from the app's side.

## What becomes public

- The address is reachable by anyone on the internet. Without a token the mail endpoint refuses every request (HTTP 401, checked live). The sign-in page and the passkey pages are open, because the passphrase and the passkey are their proof.
- Mail to `external` recipients still needs the passkey approval of the exact draft ([decision 0006](decisions/0006-approval-outside-the-chat.md)). Phone access does not change that.
- Tailscale says that machine names appear in public certificate logs. The address contains the name of the computer. If the name says something private, rename the computer in Tailscale before switching the tunnel on.
- The computer must be on, awake and signed in, and Tailscale must be running, for the phone to reach it.

## Requirements

- A Tailscale account. According to Tailscale's documentation there is no sign-up with e-mail and password, you sign in with an existing account (for example Apple, Google, Microsoft or GitHub). Plans and terms are Tailscale's and can change; read them there.
- Funnel needs MagicDNS and HTTPS certificates in the Tailscale network, and the first use asks for a confirmation on a Tailscale page. The wizard opens the right page and checks again afterwards.
- The wizard installs nothing and signs in to nothing for you.

## Switching it off (the way back)

On the first page of the wizard, choose "Only on this computer" while phone access is on, tick the box and confirm. The steps run in this order, and each can be repeated:

1. The Funnel rule is switched off (`tailscale funnel --https=443 off`). If Tailscale is missing, stopped or unreadable, this step is skipped with a note and the rest runs. A rule of somebody else, or one that cannot be read, is never touched.
2. The background service is stopped, and the wizard waits until the port is free.
3. All sign-ins on the phone are ended and the passphrase becomes invalid.
4. The service file and `remote.json` are deleted.

What stays: the mailbox, the recipients, the passkey of the computer, **the passkey of the phone** (remove it in the passkey tile if you want it gone), and Tailscale itself.

What the app cannot do: remove the connector entry in claude.ai. Remove it there yourself (Settings, Connectors).

Switching phone access on again later needs a new passphrase, a new connector entry and a new passkey on the phone.

## What was checked

- Python tests with a stand-in for `launchctl` and for the `tailscale` program, including the failing cases of the way back (Funnel cannot be switched off, Tailscale does not answer, somebody else's rule).
- Live on one Mac: service start without a keychain dialog, public address answers 401 without a token and serves the OAuth description, switching off removes service, rule and files (checked with `launchctl`, `lsof`, `tailscale funnel status`), then switching on again through the wizard.
- Live with one iPhone: connector sign-in with the passphrase, a passkey on the phone, a test mail sent from the Claude app on the phone.
- **Not yet checked live with this version of the approval page:** approving a mail to a recipient who is not yours (passkey prompt, then "Approved" and "Close this page"). The enrollment page, which shares the same script, was checked.

## Voice mode on the iPhone

**Observed, not explained.** On one iPhone in November 2026, the voice mode of the Claude app did not show the connector while its tools had real mail names such as `list_recipients`. Text chat showed it. A test series with test connectors on the author's server gave this picture:

- Tools named `tool_1` to `tool_8`: visible in voice mode. A server with a single tool `ping`: visible.
- A single tool named `list_recipients` (with a dummy answer): not visible. Eight, four or four other real tools: not visible.
- Real descriptions, argument names, the server title and the server instructions did **not** trigger it: with neutral names and all of those, the connector was visible.
- The same result with only Drive, the Mail Assistant and one test connector switched on, so another connector was not the cause.

**What is not known:** which part of a name triggers it, whether Anthropic does this on purpose or it is a bug, whether it also happens on other phones or app versions, and whether it will stay this way. Nothing here was reported by Anthropic. The author's write-up of the finding, with the protocol change and the client limit: [LinkedIn post](https://www.linkedin.com/feed/update/urn:li:activity:7531258118073171969/).

**The switch.** `OUTBOX_TOOL_NAMES=neutral` (environment of the server, then restart) lists the tools as `tool_1` to `tool_8` and renames the names inside descriptions and error texts. Calls with the neutral names are mapped back to the real tools. Everything else, including the passkey approval for external recipients, stays the same. It is off by default, except in the phone setup of the wizard: it writes `"tool_names": "neutral"` into `remote.json`, and the server reads it from there (a setting in the environment still wins). The local mode for Claude Desktop keeps the real names. With the switch on, voice mode showed the recipients, sent mail to own addresses, sent mail with attachments from the allowed folders, and sent a mail to an external address after the passkey approval.

If you switch the names on or off for a connector that already exists, remove it in claude.ai and add it again. Whether claude.ai keeps the tool list from the first connection was not tested.

## Limits

- **No rate limit in front.** The sign-in limits and their known weaknesses are in [oauth-security.md](oauth-security.md): the login lockout is global (5 attempts in 15 minutes), and open client registration can be used to fill the slots for clients that never finished a sign-in (20 by default; clients with a finished sign-in have a separate limit of 200). With a Funnel, anyone can reach those pages, and the wizard puts no rate limit in front of them.
- **Changing the address breaks passkeys and connector.** They are bound to the address.
- **The passkey limit** of two counts the phone passkey too, and it stays after phone access is switched off. If the wizard says the limit is reached, remove one in the passkey tile.
- **The passphrase has to be typed once** on the device where the connector is signed in. The app does not move it between devices.
- **Language.** The wizard is in German. The passkey pages that open in the browser are in English.
- **Platforms.** macOS and Tailscale only. Windows, Linux and the other tunnel services are not built.
- **Not a server for others.** This is one person's computer reachable from that person's phone. It is not meant to serve other people.
